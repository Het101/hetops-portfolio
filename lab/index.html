          What else is watching

          Breaking it is the part you can see. Underneath run the layers a regulated platform needs, and each one was tested by attacking it.

          • GitOps

            Argo CD makes git the only way in. Delete a deployment by hand and it is recreated from git within a minute.

          • SLO

            99% of visits must succeed over any 7 days. When the error budget is spent, experiments freeze until it recovers.

          • mTLS

            Linkerd encrypts every hop from the ingress to the database. Postgres accepts four named identities only: a pod that passed the network rules was still refused.

          • Logs

            Every request, from ingress to database, lands in Elasticsearch on one timeline.

          • Audit

            The Kubernetes audit log records who did what. A shell opened in a pod raises an alert mapped to MITRE ATT&CK.

          • Runtime

            Falco watches system calls on the node and reports what actually ran inside a container, down to the command.

          • Edge

            CrowdSec spots scanners in the access logs, and their IP is blocked at Cloudflare’s edge within two minutes.

          • Images

            Every running image is scanned weekly. The first scan found 75 high and critical CVEs; today it finds none.

          Below Kubernetes

          The servers under the cluster are code too. Every change rebuilds a server from a blank machine, and the same playbook, run against both live servers, finds nothing to change.

          • Fleet

            Two servers: this one, and a second Oracle VM that joined on 25 Oct as staging. Patches and Kubernetes upgrades land there first; if anything fails, the run stops before it reaches this one. Every night the whole fleet is checked against git, and any drift shows on the change timeline.

          • OS

            SSH takes keys only, three tries, and drops dead sessions. A pending reboot is reported, never done: the same server runs every live site.

          • Runtime

            One containerd runs both the cluster and the sites, so it is pinned and held. A routine upgrade can no longer restart everything at once.

          • Upgrades

            Kubernetes went from 1.31 to 1.32 after a rehearsal on a throwaway cluster. The first live try failed safely and rolled back; the rehearsal then reproduced that exact half-upgraded state before the second try. Audit logging survived, and 16 of 16 experiments still healed afterwards. 1.32 is now past end of life, so the next three steps go through staging first: it reached 1.33 on 25 Oct, on the way to 1.35.

          • Rebuild

            The first rebuild found what the live server quietly depended on: a directory SSH creates on first login, a package nobody listed, a second copy of Ansible. Each is now in code.
