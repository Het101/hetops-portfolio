      Threadvault

      A chat migration broke 7,200 threads. The repair became an open-source CLI.

      1. The move

        A resource move replayed 7,200 Azure Communication Services chat threads onto a new resource, with participants turned off.

      2. The damage

        7,022 messages showed the wrong author, and every thread rejected replies with CommunicationError Forbidden.

      3. The repair

        Both defects were fixable only because the extract had kept each message's original sender and every participant list.

      4. The tool

        I wrote the post-mortem, then turned the repair into Threadvault: an open-source CLI that finds these failures before a migration does.

      DNS Intelligence

      An SPF record that needs more than 10 DNS lookups fails, and nested includes hide the real count.

      A domain scanner with 26 checks across DNS, TLS, security headers, DNSSEC, email authentication and reputation. It counts SPF lookups through every nested include, the way mail servers do.

      Free for one domain. Pro and Team plans, from $5 a month, add monitoring, alerts on certificate, SPF, DMARC, MX and nameserver changes, and automatic DMARC report collection.

      How I ship

      The same bar for side projects as for production. Nothing reaches main until the ring closes, and nothing reaches npm until I approve it with 2FA.

      main
      1. testNode 20, 22 and 24, plus a real run of the built artifact
      2. hygieneworkflow audit, secret scan, signed and conventional commits
      3. analyzeCodeQL security and quality queries
      4. stagenpm publish staged from CI, with provenance
      5. approvea human, with a second factor

      Signed, protected main

      Signed commits, linear history, required checks and no force-push on every repository.

      • feat(spf): count DNS lookups through nested includes
      • fix(security): block IPv4-mapped IPv6 in every written form
      • fix(auth): never build sign-in links from request headers

      Careful dependencies

      Dependabot waits 7 days before proposing a release, every Action is pinned to a commit, and new dependencies are reviewed for advisories and licences.

      Least privilege

      Read-only by design where possible, enforced by tests. Credentials hashed at rest. Releases need no stored token.
